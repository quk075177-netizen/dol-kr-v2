# 시맨틱 롤 조사 로드맵

기준일: 2026-08-07

## 배경

value-kind는 매크로 인자의 의미 종류(고유명사, 의류명, 신체부위 등)를
분류한다. 시맨틱 롤은 한 단계 더 나아가, 번역 시 **어순·조사·문체 결정에
필요한 문맥 정보**를 제공하는 계층이다.

한국어 번역에서 value-kind만으로는 해결하기 어려운 예:

```text
<<he "Robin">>가 <<clothing "school uniform">>을(를) 벗었다.
```

- `he` 매크로의 인자는 `named_npc`지만, 번역문에서는 주격 조사(가/이)가
  필요하다.
- `clothing` 매크로의 인자는 `clothing` kind지만, 번역문에서는 목적격
  조사(을/를)가 필요하다.
- 조사 선택은 value-kind가 아니라 **문장 내 역할(주어/목적어/수식어)**
  에 따라 달라진다.

시맨틱 롤은 이 문맥 정보를 CST에 부착하는 계층이다.

## 현재 상태

- value-kind: 1,626개 인자 항목 분류 완료 (1,050개 매크로).
- 시맨틱 롤: 미설계. value-kind policy에 `named_npc`, `clothing` 등의
  semantic metadata가 "기록만 하고 사용하지 않는다"로 되어 있음.
- glossary: `research/glossary-schema.md`에 설계만 있고 데이터 없음.
- 번역 파이프라인: CST 추출까지만 완료. 번역 API 호출, 번역문 삽입은
  범위 밖.

## 조사 범위

시맨틱 롤 계층이 번역 힌트로 작동하려면 다음을 알아야 한다:

### 1. 매크로 호출의 문장 내 역할 (syntactic role)

SugarCube 매크로는 텍스트 흐름 안에서 다양한 역할로 나타난다:

- **독립 문장**: `<<gagged_speech "...">>` — 매크로 출력 자체가 하나의
  문장.
- **문장 내 삽입**: `<<he "Robin">>이 말했다` — 매크로 출력이 문장의
  주어로 쓰임.
- **수식 구**: `<<clothing "uniform">>을(를)` — 매크로 출력이 명사구로
  쓰임.
- **명령/버튼**: `<<link "Next">>` — 매크로 출력이 UI 버튼 텍스트.
- **설명/상태**: `<<print $stress>>` — 변수 출력.

각 역할에 따라 번역 시 필요한 힌트가 다르다:
- 독립 문장: 완결된 문장 번역.
- 문장 내 삽입: 뒤에 올 조사 정보가 필요.
- UI 버튼: 명사구 또는 명령문, 조사 없음.
- 변수 출력: 번역 안 함.

### 2. 인접 텍스트에서 조사 힌트 추출

매크로 호출 앞뒤의 텍스트에서 조사를 추출하면 시맨틱 롤을 자동으로
유추할 수 있다:

```text
... <<he "Robin">>이 ...
                    ^^ 주격 조사 → role=subject
```

```text
... <<clothing "uniform">>을(를) ...
                          ^^^^^^ 목적격 조사 → role=object
```

이 접근은 한국어 원문이 아닌 **영어 원문**을 번역하는 것이므로, 영어
원문에는 조사가 없다. 따라서 조사 힌트 추출이 아니라, **매크로 호출
전후의 영어 텍스트 패턴**으로 문장 내 역할을 유추해야 한다:

- `<<he "Robin">> says` → 주어 역할
- `takes off <<clothing "uniform">>` → 목적어 역할
- `<<link "Next">>` 단독 줄 → UI 버튼

### 3. 매크로별 기본 역할 매핑

각 매크로가 문장에서 어떤 역할로 자주 쓰이는지 통계를 내면, 기본
시맨틱 롤을 등록할 수 있다:

| 매크로 | 빈도 높은 역할 | 번역 힌트 |
|---|---|---|
| `he`/`she`/`he_she` | 주어 (뒤에 동사) | 주격 조사 |
| `clothing`/`facewear`/`feetwear` | 목적어 또는 수식 | 목적격 또는 수식 |
| `link`/`button` | UI 버튼 | 명사구, 조사 없음 |
| `gagged_speech`/`hypnosistext` | 독립 문장 | 완결 문장 |
| `print` | 변수 출력 | 번역 안 함 |

### 4. CST tree에서의 문맥 활용

CST tree의 parent/ancestor 정보를 활용하면, 매크로 인자가 어떤
container/branch 안에 있는지 알 수 있다:

- `if` branch 안의 `gagged_speech` → 조건부 대사.
- `switch`/`case` 안의 `body_part` → 상황에 따른 신체부위.
- `for` loop 안의 텍스트 → 반복 구조.

이 정보는 청킹(번역 단위 분할) 시 "같은 if branch의 텍스트만 묶기"에
이미 사용 가능하다. 시맨틱 롤은 여기에 문장 내 역할을 추가하는 계층이다.

## 조사 순서

### S1. 매크로별 문장 내 역할 분포 조사

전 corpus에서 각 매크로 호출 전후의 텍스트 패턴을 조사한다. 각 매크로가
어떤 역할(독립 문장, 문장 내 삽입, UI 버튼, 변수 출력)로 가장 자주
쓰이는지 통계를 낸다.

### S2. 시맨틱 롤 스키마 설계

S1 결과를 바탕으로 시맨틱 롤 종류와 스키마를 설계한다. 최소 종류:

- `independent_sentence` — 독립 문장 (완결 번역)
- `sentence_subject` — 문장 내 주어 (주격 조사 힌트)
- `sentence_object` — 문장 내 목적어 (목적격 조사 힌트)
- `ui_button` — UI 버튼 텍스트 (명사구, 조사 없음)
- `variable_output` — 변수/표현식 출력 (번역 안 함)
- `modifier` — 수식 구 (관형사/부사 힌트)

### S3. 매크로별 기본 시맨틱 롤 등록

S1 통계 기반으로 각 매크로에 기본 시맨틱 롤을 등록한다. `macro-grammar.json`
또는 별도 파일(`macro-semantic-roles.yml`)로 관리한다.

### S4. 문장 경계 탐지 설계

매크로 호출이 어느 문장에 속하는지, 문장 경계를 어떻게 탐지할지 설계한다.
SugarCube 텍스트는 마침표/개행/매크로 경계가 문장 경계 후보다.

### S5. glossary 데이터 구축과 연동

`named_npc`/`clothing`/`body_part`/`location` kind의 실제 텍스트를
수집해 glossary 데이터를 구축한다. 시맨틱 롤 + glossary가 결합되면
번역 API에 구체적인 힌트를 줄 수 있다:

```text
매크로: <<he "Robin">>
  value-kind: named_npc
  시맨틱 롤: sentence_subject
  glossary: Robin → 로빈
  → 번역 힌트: "로빈이" (주격 조사)
```

## 완료 기준

- 각 매크로의 문장 내 역할 분포가 통계로 파악됨.
- 시맨틱 롤 스키마가 설계되고 10개 이상 매크로에 시범 등록됨.
- 문장 경계 탐지 방식이 설계됨.
- glossary 데이터 구축 방식이 확정됨.
- 번역 파이프라인에 시맨틱 롤이 어떻게 전달되는지 인터페이스가 정의됨.
